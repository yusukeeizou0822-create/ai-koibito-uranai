### 本番デプロイ 404エラーの解消（完了）

**症状**: mainブランチをGitHub pushしても、本番URL (https://ai-koibito-uranai.vercel.app) が404エラーになっていた。

**原因**:
1. VercelプロジェクトのFramework Presetが「Other」になっており、Next.jsとして正しくビルド・配信されていなかった
2. ダッシュボードでFramework Presetを「Next.js」に変更したが、最初は保存ボタンの押し忘れで反映されていなかった
3. 保存後、`vercel redeploy` コマンドを使ったが、これは「過去のデプロイの古いソーススナップショットを再利用する」コマンドのため、キャラクター画像追加前の古い内容のまま再デプロイされてしまい、/characters/leon.png が404のままだった

**対処**:
1. Vercelダッシュボード → Settings → Build and Deployment → Framework Preset を「Next.js」に変更し、Save
2. ローカルの最新mainブランチ（キャラ画像含む全機能入り）から `npx vercel deploy --prod --project ai-koibito-uranai --yes` を実行し、直接デプロイし直すことで解決

**確認済み項目**:
- / → 200 OK（実際のアプリのトップページ）
- /characters/leon.png → 200 OK（正しい画像）
- /chat → 未ログイン時307リダイレクト（正常な認証ガード）
- /api/auth/providers → Google認証プロバイダ情報を正常返却

### mainへのgit pushで自動デプロイがトリガーされない問題（原因判明・解決済み）

**原因**: Vercelには「同じコミットSHAが過去にデプロイ済みの場合、新しいDeploymentを作成せず、
直近の同一SHAのDeploymentをそのまま返す」という仕様がある。

developブランチにキャラ画像コミット(d8f02aa)をpush → Previewとして正常にデプロイ済み。
その後 `git merge develop`（fast-forwardマージ）によりmainが同一のコミットSHA(d8f02aa)を
指すようになったため、mainへpushしてもVercelは「このSHAは既にビルド済み」と判断し、
Production向けの新しいデプロイを作成しなかった。

Vercel側の設定（Git連携・Production Branch・GitHub App権限）はすべて正常であり、
原因はGitのマージ方法（fast-forward）にあった。

**今後の対策（次回mainへマージする際に採用）**:
- `git merge --no-ff develop` を使い、fast-forwardを禁止して必ず新しいマージコミットを
  作成する。これにより新しいSHAとなり、Vercelが確実に新規デプロイをトリガーする。
- または、Vercelダッシュボード/CLIの「Promote to Production」機能を使い、
  すでにビルド済みのdevelopのデプロイ成果物を、リビルドなしでそのままProductionに
  昇格させる方法もある。

**参考**:
- https://community.vercel.com/t/same-commit-sha-pushed-to-multiple-branches-only-creates-deployment-for-the-first-branch/44782
- https://github.com/vercel/community/discussions/1018
- https://vercel.com/docs/git/vercel-for-github

## 2026/08/05 セッション記録：Googleログイン＆AI通信エラーの解消

### 発生していた問題と原因
1. Googleログイン時に `Error 401: invalid_client`
   - 原因：Vercelの環境変数 `GOOGLE_CLIENT_ID` の値が実質空（プレースホルダー表示のみで未保存）だった
2. `invalid_client` / "The provided client secret is..." エラー
   - 原因：`GOOGLE_CLIENT_SECRET` の値も同様に不正確だった
3. キャラクターとの会話でAIとの通信エラー（"AIとの通信でエラーが発生しました"）
   - 原因：`ANTHROPIC_API_KEY` の値も同様に空（プレースホルダー表示のみ）だった
4. 上記対応後も一時的に "Server error" が表示された
   - 原因：ログイン試行中に作られた古いCookieがブラウザに残っていたため
   - シークレットウィンドウ（プライベートブラウジング）で再試行して解消

### 対応内容
- Google Cloud Console「対象」ページでテストユーザーに `yusuke.eizou.0822@gmail.com` を登録
- Google Cloud Console「クライアント」ページで新しいクライアントシークレットを発行し、Vercelの `GOOGLE_CLIENT_SECRET` に設定
- Anthropic Console（https://console.anthropic.com/settings/keys）で新しいAPIキー `ai-koibito-uranai-production` を発行し、Vercelの `ANTHROPIC_API_KEY` に設定
- Vercel環境変数を変更するたびに、Environment Variables画面の「Redeploy」から再デプロイを実施

### 得られた教訓・今後の運用への追加ルール
- **Vercelの環境変数（Sensitive設定のもの）は、保存前に表示されている値が「薄いグレー文字（プレースホルダー）」なのか「黒字の実際の値（保存済み）」なのか、必ず見分けてから作業する。**
  グレー文字のまま「保存済み」と誤認したことが、今回の複数の問題（GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, ANTHROPIC_API_KEY）すべての根本原因だった。
- 環境変数を変更したら、必ず再デプロイ（Redeploy）が必要。保存しただけでは本番に反映されない。
- ログイン関連の動作確認は、Cookieの影響を避けるため、シークレットウィンドウで行うと切り分けがしやすい。
- エラーの原因調査はVercelの「Logs」画面で、該当行をクリック→詳細パネルの「Logs」セクションで具体的なエラーメッセージ（例：`[auth][error] InvalidCheck`、`Claude API error: 401 authentication_error` 等）を確認するのが有効。

### 得られた教訓・今後の運用への追加ルール
- クライアントコンポーネント（'use client'）化する際は、importしているファイルがバレルファイル（index.ts等）でサーバー専用コードも一緒にエクスポートしていないか要注意。型定義など軽量な部分だけを別ファイルに切り出し、そこから直接importするのが安全
- VS Code上でClaude Codeの「Do you want to make this edit」等の確認プロンプトに対し、内容を精査せず反射的に「No」を選ぶと、その後の別の作業（動作確認等）の文脈と噛み合わなくなり、原因調査に時間がかかることがある。確認プロンプトが出たら、直前のチャット上の指示内容と一致するかどうかをまず確認してから選択する
